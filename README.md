## TikTok 直播到底需要什么样的网络

### 先算带宽，再谈线路

TikTok Live Studio 本身提供 720P 和 1080P 画质档位，画质越高对上行带宽的要求越高。知乎上一篇讲手机直播专线选择的文章给出的参考值是：720P 稳定推流大约需要 2-4Mbps 上行，1080P 需要 6-10Mbps。华纳云的技术文档则建议把推流码率控制在稳定上传带宽的 70% 左右，给网络抖动留余量——比如 10Mbps 的稳定上传，推流码率设在 6000-7000kbps 比较稳妥。

再叠加两个常被忽略的变量：

- **并发**。矩阵号同时开播时，带宽要按"每个直播间预留 5-10Mbps 上行"来算，这是第三方直播网络指南里的通用口径。
- **持续性**。直播是数小时的连续上传任务，"峰值带宽"不等于"持续跑满"。Mkcloud 官方知识库也明确说：共享带宽为峰值，不保证持续跑满。所以看套餐时，流量配额和峰值数字之外，更要关心计费方式。

一个简单的自查方法：先用测速工具确认你本地出口的持续上行，再对照目标码率留出两倍余量。连这个数都凑不出来，换再贵的专线也解决不了本地这头的问题。

### 延迟看什么

有第三方整理的选线清单给过一个参考区间：香港出口端内延迟≤5ms、日本≤30ms、美国≤130ms。拿这个区间对照 Mkcloud 官方挂出的端内延迟，三条主力线刚好一一对应——广港 IEPL 1~2ms、沪日 IPLC 25~28ms、沪美 IPLC 124~134ms。这些数字是"端内延迟"（国内入口到出口段），不是你本地到直播间观众的全程延迟，但线路质量主要就卡在这一段。

注意一个容易搞混的点：延迟影响的是互动实时性，推流卡不卡更多取决于持续上行和丢包。做美区直播选沪美 124~134ms 是物理距离决定的，不用因为"延迟比香港高"就觉得线路差。

### IP 环境：专线能解决什么、不能解决什么

这是最值得抄下来的一段。Mkcloud 官方知识库的原话说得非常直白：

> 独享 IP 不保证平台批准账号、不限流或不封号。视频播放量、账号审核或推荐异常不是单靠买专线就能解决；出口地区也不能代替账户使用资格。

翻译一下：专线解决的是"网络路径质量"——持续上传、抖动、丢包、IP 独占。但账号资格、内容合规、风控判断，是平台侧的事。官方还提醒了一个技术细节：如果你的推流程序跑在本地，通过远程桌面连上 VPS 并不会自动把本地推流改走它，先想清楚业务到底运行在哪一端。

| 普通 VPS | 30-100元 | 独享但线路绕 | 轻度起号测试 | 晚高峰绕路丢包，推流掉帧 |

IEPL 和 IPLC 的区别简单说：两者都是物理隔离的跨境专线，不走公网拥堵路由，区别在接入方式（IEPL 是以太网专线对接，IPLC 是传统点对点私有线路）。IX 则是走互联网交换中心的优化入口，价格低一档，但对入口有要求——后面细说。

第三个方案里 Mkcloud 的差异化点是"双端独立 IP"：每台 VPS 有 1 个独立入口 IP 和 1 个独立出口 IP。对做矩阵号的团队，官方知识库给的组网思路是一账号→一 VPS→一条线→一个 IP，用独享专线做到"一店一 IP"。这不是防封保证，但至少避免了共享代理池里"别人干了坏事连累你的 IP"这种最冤的死法。
